# Dir Shopping Store

A multi-vendor online shopping marketplace built with Flutter + Firebase.

This repository is **Phase 1** of the full project: the app scaffold,
theming, routing, data-model foundation, and a complete, working
authentication system. Later phases build the customer app, seller
dashboard, shop/product/order features, and admin panel on top of this
foundation — see **Roadmap** below.

## What's included in this phase

- Flutter project scaffold: `lib/core` (theme, routing, shared widgets,
  validators, constants), `lib/models`, `lib/features`.
- Material 3 theme, light + dark mode.
- go_router navigation with auth-aware redirects (splash → onboarding →
  login/register → email verification → home).
- Full authentication, wired to Firebase Auth + Firestore:
  - Email/password registration with email verification
  - Email/password login, with "remember me"
  - Google Sign-In
  - Forgot password / reset email
  - Email-verification waiting screen that polls and auto-continues
  - Logout
- `users/{uid}` Firestore schema + security rules.
- Firestore & Storage security rules for the full planned schema
  (shops, products, orders, reviews, etc.) so later phases can build
  directly on them.
- Riverpod state management throughout.

## What's NOT in this phase (by design)

This app is not runnable "as-is" straight out of the box, for two
unavoidable reasons, both fixed by steps below:

1. **No Android/iOS native projects yet.** Those are large, mostly
   auto-generated folders (Gradle files, Xcode project, etc.) that
   Flutter's own tooling (`flutter create`) generates far more
   reliably than hand-writing them. Step 1 below generates them.
2. **No live Firebase project.** `lib/firebase_options.dart` is a
   placeholder — Firebase credentials are unique to *your* Firebase
   project and can't be pre-generated. Step 2 below wires up a real
   project in a few minutes with the official CLI.

## Setup

### 1. Generate native projects

```bash
flutter create --project-name dir_shopping_store --org com.dirshoppingstore .
```

Run this **in this folder** — it will add `android/`, `ios/`, etc.
without touching the `lib/` and `pubspec.yaml` already here (say yes if
it asks to overwrite `pubspec.yaml`... actually don't: keep this one,
since it already lists every package this project needs).

If prompted about overwriting `pubspec.yaml`, choose **No** — this
repo's `pubspec.yaml` already has every dependency the app needs.

### 2. Create a Firebase project & connect it

```bash
npm install -g firebase-tools   # if you don't have it
firebase login

dart pub global activate flutterfire_cli
flutterfire configure
```

Follow the prompts: create (or pick) a Firebase project, select
Android + iOS, and let it register your app's bundle ID. This
overwrites `lib/firebase_options.dart` with real values.

In the Firebase console, enable:
- **Authentication** → Sign-in method → Email/Password, Google
- **Firestore Database** (start in production mode)
- **Storage**
- **Cloud Messaging**, **Analytics**, **Crashlytics** (enable, no extra config needed yet)

Deploy the security rules included in this repo:

```bash
firebase deploy --only firestore:rules,storage:rules
```

### 3. Android permissions

`flutterfire configure` handles the `google-services.json` wiring, but
you'll want these permissions in `android/app/src/main/AndroidManifest.xml`
(inside `<manifest>`, outside `<application>`) once later phases add
maps, camera uploads, and notifications:

```xml
<uses-permission android:name="android.permission.INTERNET"/>
<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION"/>
<uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION"/>
<uses-permission android:name="android.permission.CAMERA"/>
<uses-permission android:name="android.permission.READ_EXTERNAL_STORAGE"/>
<uses-permission android:name="android.permission.POST_NOTIFICATIONS"/>
```

### 4. Install packages & run

```bash
flutter pub get
flutter run
```

## Project structure

```
lib/
  main.dart                 # entry point, Firebase init
  app.dart                  # MaterialApp.router root widget
  firebase_options.dart     # regenerated by flutterfire configure
  core/
    theme/                  # colors, text styles, ThemeData
    routing/                # go_router config + auth redirects
    constants/               # app-wide + Firestore path constants
    utils/                  # validators
    widgets/                # PrimaryButton, CustomTextField, LoadingOverlay
  models/
    user_model.dart
  features/
    auth/
      data/                 # AuthRepository (FirebaseAuth + Firestore)
      providers/            # Riverpod providers + AuthController
      screens/              # splash, onboarding, login, register,
                             # forgot-password, email-verification
      widgets/               # SocialLoginButton
    home/
      screens/               # placeholder authenticated landing screen
```

## Roadmap (next phases)

- **Phase 2 — Customer app core:** Home (featured/latest/trending),
  categories, product detail, search & filters, cart, checkout, order
  tracking, wishlist, reviews. Adds `shop_model.dart`,
  `product_model.dart`, `order_model.dart`.
- **Phase 3 — Seller dashboard:** shop setup/edit, product CRUD with
  multi-image/video upload, order management, sales analytics,
  EasyPaisa/JazzCash payment-proof verification flow.
- **Phase 4 — Admin panel:** user/shop/product/order/report
  moderation, analytics dashboards, category management.
- **Phase 5 — AI features:** product title/description/tag generation,
  smart search, recommendations, spam/fake-review detection (via a
  Cloud Function calling the Anthropic or OpenAI API — never call an
  LLM API key directly from the client).
- **Phase 6 — Polish:** push notifications, offline caching, shimmer
  loading states everywhere, app icon/splash asset generation, store
  listing assets.

## Notes on payments

EasyPaisa and JazzCash don't offer a public consumer-facing payment
API for individual sellers — the design here (and the brief) is
screenshot-based manual verification: buyer pays to the seller's
EasyPaisa/JazzCash number, uploads a screenshot, seller marks the
order Confirmed. That's reflected in the `orders` Storage rules
(`orders/{orderId}/payment_proof.jpg`) already in this repo.
